# 更新日志 Changelog

## 1.3.1

> 适用版本：Minecraft **1.21.1**（NeoForge 21.1.248+）与 Minecraft **26.1.2**（NeoForge 26.1.2.97+）

### 新增 · 八枚遗迹戒指的属性加成与闪避

- **每枚遗迹戒指现在都带一份自己的属性**（`RelicBonuses`，只在戴进 Curios 飞行戒指槽时生效，与三枚联动戒指同一套通道）：

  | 戒指 | 属性 |
  |---|---|
  | 幽匿 | +20 攻击伤害、+10% 攻击速度、+2 方块与生物触及 |
  | 矿工 | +5 方块触及、+2 护甲与韧性 |
  | 绿宝石 | +2 生物触及、+5 护甲与韧性、+10 最大生命 |
  | 海洋 | +10% 移动速度、+25% 闪避、+10 最大生命 |
  | 荒漠 | +30 最大生命、+10 护甲与韧性、+50% 闪避、**+10 幸运**（原为 +1） |
  | 劫掠 | +25% 攻击伤害、+10% 攻击速度、+4 护甲与韧性、+2 生物触及 |
  | 炼狱 | +20 攻击伤害、+20% 攻击速度、+8 护甲、+4 韧性、+2 生物触及 |
  | 末影 | +10 方块触及、+2 生物触及、+3 护甲与韧性、+20% 闪避 |

  平铺值用 `ADD_VALUE`、百分比用 `ADD_MULTIPLIED_BASE`（写入前 ÷100，所以"10"就是 +10%）。**属性不在 tooltip 里另写一行**：
  Curios 会把「戴进饰品槽才生效」的属性列在物品 tooltip 底部（神话的闪避属性也出现在那里），所以本 mod 不重复列一遍。
  **攻击伤害的两条是平铺 +20**（不是 +20%），这是用户明确的选择。
- **闪避沿用「神话」（ApothicAttributes）的机制**（用户点名参考，我把 `ApothicAttributes-1.21.1-2.10.1`
  与 `-26.1.2-3.0.1` 的字节码读了）：
  - 它把闪避做成属性 **`apothic_attributes:dodge_chance`**（NeoForge `PercentageAttribute`，存的是分数，
    +0.25 显示为 +25%），只在**近战**（攻击者是玩家要求 `distanceToSqr ≤ 生物触及²`，是生物要求
    `isWithinMeleeAttackRange`）与**弹射物命中**（`ProjectileImpactEvent`）时判定，**环境伤害一律不闪**；
    掷骰是**逐 tick 确定性**的（种子 = `tickCount + uuid.hashCode()` 过一遍 `0x9E3779B9` 混合），
    反馈是它自带的 `dodge` 音效 + 6 颗 `LARGE_SMOKE`。
  - **兼容做法**：装了 ApothicAttributes 时，我们的闪避值通过 Curios 直接加进**它的**属性，由**它的**处理器掷骰 ——
    全局只掷一次、音效与属性面板都统一，不会双重判定。属性按 **id 运行时查找**（`ApothicAttributesCompat`），
    所以本 mod 对神话**零编译期、零运行时依赖**（与 Allthemodium 联动同一套思路）。
  - **没装神话时**由 `RelicDodgeHandler` 用**完全相同**的规则自己掷骰（同样的两处判定、同样的确定性种子、
    同样的反馈，音效用原版 `PLAYER_ATTACK_SWEEP` + 同样的烟雾）。
  - **没装神话时闪避同样要显示在 tooltip 底部**：本 mod 注册了自己的 **`simpleflightring:dodge_chance`**
    （同为 NeoForge `PercentageAttribute`，范围 0..1，+0.25 显示 "+25%"），并用 `EntityAttributeModificationEvent`
    把它加进**玩家**的属性表，于是 Curios 照常把它列在物品 tooltip 的属性组里；`RelicDodgeHandler` 直接读这条属性掷骰。
    **装了神话时一滴都不会加到自己这条上** —— `ApothicAttributesCompat#dodgeTarget()` 优先返回神话的属性，
    所以任何情况下都只有一条闪避属性、只掷一次骰。
- 探针实测（两版本各 **58 项 ALL PASS**）：八枚戒指的数值表与用户给定的一致；每枚戒指都把附加值挂到了自己身上
  （普通戒指/联动戒指为 `null`）；修饰符的数值与 `Operation` 正确（含 ÷100 的百分比与荒漠那条 `LUCK 10`）；
  未装神话时不产生闪避属性、由自有处理器接管；50% 掷骰 1000 tick 命中 524 次且**同一 tick 结果稳定**、
  0% 永不触发、100% 必触发；中英 lang 键集合一致（**183 键**）。

## 1.3.0

> 适用版本：Minecraft **1.21.1**（NeoForge 21.1.248+）与 Minecraft **26.1.2**（NeoForge 26.1.2.97+）

### 新增 · 八枚遗迹飞行戒指（只能捡到损坏版）

- **幽匿 / 矿工 / 绿宝石 / 海洋 / 荒漠 / 劫掠 / 炼狱 / 末影飞行戒指**：没有任何合成配方，
  损坏版按主题分布在不同结构的箱子中，**每箱 2%** 概率开出（**矿工戒指 4%**，因为它对标铁戒指、
  且要多一步爆破重塑）：
  远古城市 / 废弃矿井（箱子矿车）/ 沉船（宝藏箱与补给箱）/ 沙漠神殿 / 掠夺者哨塔 / 林地府邸 /
  下界要塞 / 末地城。**绿宝石飞行戒指**不走战利品，改由**大师级图书管理员**出售
  （32 绿宝石、3 次、30 经验，且只有 **50%** 概率刷出，见下）。
- 损坏戒指是独立物品：不能飞行、不能装入 Curios 饰品槽、无法附魔，tooltip 写明所需修复材料。
- 修复配方为**工作台无序合成**（损坏戒指 + 1 个主题材料 → 完好戒指），材料依次为：
  回响碎片 / 铁块 / 绿宝石块 / 海洋之心 / 不祥之瓶 / 烈焰棒 / 潜影壳
  （幽匿 / 矿工 / 绿宝石三枚改为任务链，海洋与荒漠另有各自的摆放配方，见下）。
- 各戒指飞行时间：幽匿 120 分钟（对标钻石戒指）、**矿工 30 分钟（对标铁戒指）**、绿宝石 60、海洋 120、
  **荒漠 30 分钟（对标铁戒指）**、劫掠 140、炼狱 150、末影 240。
- 幽匿戒指采用**原版幽匿块配色**（暗青系）并做了**呼吸灯动画**：`16×128`（8 帧）+ `.mcmeta`（`frametime: 10`、`interpolate: true`），周期 4 秒与原版幽匿块一致；金属上散布 5 个青色亮点，各自相位不同、明暗呼吸。
- 8 枚新戒指已加入 `#simpleflightring:flight_rings`、`curios:flight_ring`（可佩戴）与
  `enchantable/durability`、`enchantable/mining`（可附魔）标签，也可继续用「不毁核心」变为不毁。

### 新增 · 幽匿戒指的两段式任务链

- 损坏的幽匿戒指不再用普通修复配方，tooltip 改为灰色「戒指已失去了远古的力量」+ 幽匿蓝
  「戒指在渴望监守者的灵魂」；**携带它击杀监守者**后戒指吞噬灵魂、带附魔光效，第二行变为
  「戒指需要一个新的躯壳」。**一只监守者只对应一枚戒指**（多枚损坏戒指各自需要一次击杀）。
- 新组件 `simpleflightring:warden_soul` 记录该状态；配方改为**工作台：8 个回响碎片围一圈 +
  中间已充能的损坏戒指 → 幽匿飞行戒指**（旧的 shapeless 修复配方已删除，未充能的戒指无法合成）。
- 击杀反馈：幽匿催化体音效 + 灵魂粒子 + 动作栏提示。

### 新增 · 幽匿戒指的特殊能力「幽匿之魂」

- 需要**戴在 Curios 飞行戒指槽**才生效（与其他特殊戒指一致）：
  1. **免疫失明/黑暗**：新效果根本挂不上，戴上戒指时身上已有的失明/黑暗也会被清除；
  2. **监守者视你为同类**：监守者完全不会把你选为目标（原版它走 brain 记忆 `ATTACK_TARGET`、不触发任何事件，
     所以用 Warden mixin 拦 `canTargetEntity`）；主动攻击它后 10 秒内它仍会还手；
  3. **深暗之域保持安静**：取消你的音效与**振动**（游戏事件），并额外拦下 `SculkShriekerBlockEntity#tryShriek`
     —— 站在尖啸体上也不会触发、不会招来监守者；
  4. **V 键音波攻击**：照抄原版监守者音波（10 点伤害 + 原版击退 + 沿光束粒子 + 音效），内置 3 秒 CD。
- tooltip 的 Shift 展开块新增 5 行说明，最后一行**动态显示当前绑定的按键**。

### 新增 · 矿工戒指的两段式任务链与「矿道老手」

- 损坏的矿工戒指 tooltip：淡灰「不知是哪一任矿工留下的戒指」、淡灰「斑驳的材质诉说着它早已损坏」、
  白色「需要使用爆破的力量重塑」；**把这枚损坏戒指扔在地上让一次爆炸波及它**（TNT / 苦力怕 / 其他模组爆炸都行）
  → 戒指被"爆破重塑"、**自身不会被炸毁**、带附魔光效，第三行变为白色「只需再填补材料就能恢复如初」。
- 新组件 `simpleflightring:blast_forged` 记录该状态；配方为**工作台：8 个铁锭围一圈 + 中间已重塑的损坏戒指
  → 矿工飞行戒指**（旧的 shapeless 修复配方已删除）。
- 矿工戒指耐久**对标铁戒指**（1800 / 30 分钟），但**自带耐久 I**（内置附魔，砂轮洗不掉，tooltip 显示"自带 耐久 I"）。
- **「矿道老手」能力**（淡灰色，需戴在 Curios 槽）：①永久夜视（30 秒 buff 每秒续，图标可见、不闪烁，摘戒指/耐久耗尽立即清除）
  ②急迫随深度：海平面以下 I、y<0 II、y<-32 III，其他维度固定 I ③**免疫一切爆炸**（伤害与击退都免疫，
  方块/生物/其他模组都算）④**V 键矿道爆破**：以自身为中心的原版 TNT 爆炸（破坏方块，自己免疫），3 秒 CD，
  冷却提示"爆破炸药装填还需 x 秒"。第四条说明文字改为**「永久获得夜视和急迫效果且免疫爆炸」**（把免疫爆炸写进同一行）。

### 新增 · 绿宝石戒指的袭击任务链与「新秀英雄」

- 大师级图书管理员的出售**不再是必然**：每只图书管理员晋升大师时只有 **50%** 概率刷出这笔交易
  （1.21.1 让 `ItemListing` 返回 `null`，26.1.2 用 `merchant_predicate: minecraft:random_chance 0.5`），
  所以得多找几位管理员碰运气；刷出来的仍是 32 绿宝石 / 3 次 / 30 经验。
- 损坏的绿宝石戒指**改为两段式任务链**，tooltip 三行淡灰 + 一行白色：
  「昔日英雄早已离去」/「斑驳的戒指铭刻着的英雄二字」/「它诉说着以往的光辉事迹」/
  白「再守护一次村庄来唤醒它吧」。
- **带着它在任意一场袭击（Raid）中取得胜利**即唤醒戒指：新组件 `simpleflightring:hero_charged`、
  带附魔光效，tooltip 第四行变白**「戒指感受到了昔日的光辉(I~V)」**并追加第五行**「现在需要重铸一份新的媒介」**。
  一场胜利只唤醒**一枚**戒指（同时带多枚时要各打一场）。
  判定走原版 `ServerLevel#getRaidAt`（玩家 96 格内的活动袭击）+ `Raid#isVictory()`，每秒轮询一次；
  胜利后原版还有 30 秒庆祝期，窗口足够。反馈：快乐村民粒子 + 进度达成音效 + 动作栏「戒指在村庄的胜利中苏醒(I~V)」。
- **戒指强度 = 袭击的不祥之兆等级（1~5）**，与原版村庄英雄的 1~5 级一一对应：
  带损坏戒指打**几级袭击**，唤醒后括号里就是**几**，合成出的成品戒指也提供**同等级**的村庄英雄。
  等级存在新组件 `simpleflightring:hero_level`（整数 1~5，缺省按 I 处理，兼容旧存档里的已充能戒指），
  tooltip 用罗马数字显示、括号保留；buff 的 amplifier 就是 `等级 - 1`。
- **已经唤醒/已经合成**的戒指还能继续变强：在**更高等级**的袭击中获胜就会把它的等级提升到该袭击的等级
  （同级或更低不会有变化）。**已经 V 级的戒指不会吸收这场胜利，会顺延给其他戒指**
  （先看有没有沉睡的损坏戒指可唤醒，再看有没有等级更低的），一枚符合条件都没有时这场胜利什么都不做，
  庆祝期内拿到新戒指仍然有效。同一次胜利里**唤醒优先于升级**。动作栏提示为
  「戒指从这场胜利中汲取了更耀眼的光辉(I~V)」。
- 合成时等级会从损坏戒指**带到成品**：这里没有用原版 `minecraft:crafting_shaped`，而是新配方类型
  **`simpleflightring:emerald_forge`**（`EmeraldForgeRecipe`，3×3 图案 + 中间那枚已唤醒的损坏戒指）。
  原因有两个：原版配方**永远不会把原料的组件拷到产物**上；而且合成台**结果预览就是用 `assemble(输入)`
  算出来的**（`CraftingMenu#slotChangedCraftingGrid`），所以用原版配方时预览一直显示 I 级，必须取出才变。
  自定义配方直接在 `assemble` 里读中间那枚戒指的 `hero_level`，**预览和取出后的成品都是正确等级**，
  不再需要任何取出后补救的逻辑。
- **创造物品栏 / `/give` 拿到的绿宝石戒指是 5 级**：`hero_level` 作为**默认组件**写在物品上（缺省 V），
  所以从创造栏拿的、`/give` 出来的都是满级戒指；合成出来的戒指会在 `assemble` 里被覆盖成损坏戒指的等级。
- 重铸配方**工作台：8 个绿宝石围一圈 + 中间已唤醒的损坏戒指 → 绿宝石飞行戒指**
  （旧的 shapeless「损坏戒指 + 绿宝石块」修复配方已删除，未唤醒的戒指无法合成）。
- 绿宝石戒指耐久**对标金戒指**（3600 / 60 分钟），并**自带效率 I**（内置附魔，砂轮洗不掉）。
- **「新秀英雄」能力**（绿宝石绿，需戴在 Curios 槽；**纯被动、没有主动能力**，因此吃不到「能量迸发」），
  tooltip 四行：
  1. **永久村庄英雄**：30 秒 buff 每秒续，图标可见、不闪烁，摘戒指 / 耐久耗尽立即清除；
  2. **对灾厄村民造成的伤害翻倍**（`#minecraft:raiders`：掠夺者 / 卫道士 / 唤魔者 / 劫掠兽 / 幻术师 / 女巫；
     近战、弓箭等一切"以你为攻击者"的伤害都算）；
  3. **击杀灾厄村民掉落物翻倍**：在原版已经结算完抢夺之后执行，所以**与抢夺附魔叠加**；
     会溢出的堆叠会拆成多份而不是被截断，因此十字弓、旗帜这类单件掉落也真的掉两份；
  4. **击杀任意敌对生物有 10% 概率额外掉落 1 个绿宝石**（`Enemy`，即僵尸/骷髅/蜘蛛等一切敌对生物，
     不叠抢夺；遵循原版 `doMobLoot` 规则，关掉生物掉落时不会掉）。这一条**不单独占 tooltip 行**。

### 修复 · 1.21.1 客户端身上有「永恒灵魂火」时会闪退

- **症状**：客户端只要有任何实体带着这个 debuff 就会被踢回桌面 —— 报
  `ClassCastException: ClientLevel cannot be cast to ServerLevel`，位置是
  `EternalSoulFireEffect#applyEffectTick` 里的 `(ServerLevel) target.level()`。
- **原因**：1.21.1 的 `LivingEntity#tickEffects` **两端都会跑**，所以效果逻辑（伤害、净化、强制无限时长、灵魂火粒子）
  在客户端也会被调用，而其中粒子那段需要一个 `ServerLevel`。**26.1.2 没有这个问题**——那边 API 直接把
  `ServerLevel` 作为参数传进来，而且只在 `MobEffectInstance#tickServer` 里调用（顺手确认过）。
- **修法**：`applyEffectTick` 开头加客户端守卫（`target.level().isClientSide()` 直接 `return true`）：这些东西本来就是
  服务器的决定，客户端只负责显示服务器发来的粒子。另外把 `InfernalRingQuest#quench` 里的裸转换改成
  `instanceof ServerLevel` 提前返回，避免以后重构时再踩同类坑。

  反馈：灵魂火粒子 + `FIRECHARGE_USE` + 动作栏**「凋零的灵魂已被古老的火焰领主吸收」**。
- **第二步：把充能的损坏戒指丢进岩浆**——岩浆**当场把它淬炼成成品炼狱戒指**（动作栏**「媒介已被熔岩重塑」**、
  熄灭音效 + 灵魂火粒子），旧的「损坏戒指 + 烈焰棒」占位配方**已删除**。
- **两步顺序强制**：没杀过凋零的损坏戒指丢进岩浆只会浮着，捞出来仍是损坏态。
- **两个形态都像下界合金一样不怕岩浆**（`Item.Properties#fireResistant()`，原版 `ItemEntity#fireImmune` 认的就是这个组件）。
- **岩浆里的过程照原版"把物品扔进水里"来做**（`InfernalRingLavaMixin`，`ItemEntity#tick` 的 TAIL 注入，两端都跑，纯物理所以客户端也要一起算）：
  戒指先**带着落下的速度扎进液面下**（探针实测从液面 102.889 沉到 100.004，约 2.9 格），停住之后再**自己浮上来**，最后**定在液面下 0.05 格不动**。
  两处与原版的差异都是按手感调的：①**下沉**在岩浆自身阻尼之外再乘 0.9（岩浆比水稠，不然高速扔进去会一路沉到岩浆海底部）；
  ②**上浮**每 tick 直接给 0.025 格/秒的竖直速度（实际约 0.5 格/秒），比原版水里（0.33 格/秒）快一点点——岩浆不透明，太慢会让人以为戒指没了。
  ③**状态标记用 `noGravity`**：它在"戒指还在下潜"时是 false（下潜完全交给原版流体物理），落定那一刻置 true（`noGravity` 正好就是"岩浆在托着它"的物理含义），
  而它同时解决了**浮在水面的物品本来会一直上下起伏**的问题（原版一到水面就重新吃重力）——所以戒指浮上来后是**真正定住**的；离开岩浆时立刻清回 false，不影响戒指的其它任何行为。
  ④**让它不过期不能靠把 `age` 归零**（第一版就是这么写的，1.21.1 实测"戒指在岩浆里不旋转、一直抽搐"）：1.21.1 的物品**旋转角**与浮在水面时的**上下浮动**都由 `ItemEntity#getAge()` 算（`ItemEntity#getSpin` 与 `ItemEntityRenderer`），
  把 `age` 冻住等于把旋转冻住、只剩每帧插值那点抖动；**26.1.2 用的是 `EntityRenderState.ageInTicks`（= `tickCount`），所以同一个 bug 在 26.1.2 上完全看不出来**。
  现在改成**每 tick 把 `lifespan` 推到 `age + 6000`**（原版会把 `Lifespan` 一起存档，重启也保得住；只在戒指真的在岩浆里时才推），戒指照常旋转、也永远不会过期消失。

### 新增 · 末影戒指的能力「亚空间枢纽」

- 第八枚、也是最后一枚遗迹戒指（末地城宝箱，能力名取自战锤）。**被动四条**，需要戴在 Curios 槽且戒指可用：
  1. **末影生物中立**：末影人 / 末影螨 / 潜影贝 / 幻翼视佩戴者为同类（新数据包标签 `warp_nexus_neutrals` +
     `LivingChangeTargetEvent` 清目标，与海洋 / 荒漠 / 劫掠戒指同一套写法），**主动攻击仍会还手**
     （`LivingIncomingDamageEvent` 记仇，按存活 / 同维度 / 跟随距离校验）；
  2. **注视不再激怒末影人**：走的是 NeoForge 自己的 **`EnderManAngerEvent`**（南瓜头用的是同一个钩子；1.21.1 在
     `isLookingAtMe` 里经 `CommonHooks.shouldSuppressEnderManAnger` 触发，26.1.2 在怒气判定里调用），**没有自己 mixin 重写**；
  3. **不再召唤幻翼**：NeoForge 的 **`PlayerSpawnPhantomsEvent`** 直接回 `DENY`（原版 `PhantomSpawner` 对每个玩家生成前都会问这个事件），
     **连 mixin 都不需要**；
  4. **免疫漂浮**：`MobEffectEvent.Applicable` 拒绝新实例，**并在戴上戒指的那一刻清掉身上已有的**（边沿触发，照荒漠戒指治饥饿 / 中毒的写法；
     这是条附带效果，**不占 tooltip 行**——用户指定）。
- **弹射物会被随机传送**（`WarpNexusProjectiles`）：照 `KineticDeflectionHandler` 的三段式（`ServerTickEvent.Pre` 的球形屏障 +
  `ProjectileImpactEvent` + `LivingIncomingDamageEvent` 兜底），但处理方式从"弹开"改成"**送走**"——随机方向 8~16 格、随机新速度，
  两端各来一次传送门粒子 + 末影传送音效，佩戴者掉血为 0。屏障**只处理"仍在靠近"的弹射物**（`approach ≥ 0.1`），
  所以**已经插在地上 / 墙上、或正在减速的箭不会再被误送走**（实测：插在 1 格处的箭不动，飞来的箭照旧被送走）。
- **V 键向目标点瞬移**（`WarpNexusAbility`）：基础 **15 格** × `abilityDamageMultiplier`（能量迸发 V 级 = 33.75 格），**冷却 5 秒**（用户指定）。
  落点逻辑**照抄 Just Dire Things 的蚀空门径手杖**（用户点名的参考，我把 1.5.7 的 `AbilityMethods#voidShift` 字节码读了：它是
  `player.pick(distance, …)` 做方块射线、命中就落在那个方块面前，外加 `worldBorder.isWithinBounds` 与 `resetFallDistance`）——
  本实现先用**眼位锚定的方块射线**把距离压到"命中点前 0.35 格"，再沿视线每 0.25 格找能站的地方：**台阶 / 斜坡最多抬升 1.25 格**、
  **除水以外的流体一律当方块且绝不抬出液面**（岩浆与其它 mod 的流体都进不去），世界边界也算墙；
  **墙挡在眼前（连 1 格都过不去）→ 原地不动、也不进冷却**（沿用矿工戒指"失败不进 CD"的规矩）。
  落地后有一次**坠落伤害豁免**（`LivingFallEvent` 取消 + `resetFallDistance`，一落地就解除）。戒指自带**火箭加速 I**。
- 成品 tooltip（用户定稿，四行 + 主题色标题）：**「你将能够掌握末影的力量」**、**「末影生物将不再以你为敌」**、

## 1.2.0

> 适用版本：Minecraft **1.21.1**（NeoForge 21.1.248+）与 Minecraft **26.1.2**（NeoForge 26.1.2.97+）

### 新增 · Allthemodium 联动（可选，需安装 Allthemodium）

- **三枚联动戒指**：ATM 飞行戒指 / 振金飞行戒指 / 难得素飞行戒指，**合成即不毁**。
  - 属性（护甲、韧性、攻击力、触及距离）与特殊能力**仅在佩戴于 Curios 饰品槽时生效**，放在背包里仍只提供飞行。
  - 升级链的起点——下界合金戒指——必须**先**与**不毁核心**（1 下界合金锭 + 1 下界之星，无序合成）在锻造台合成变为不毁，之后沿链条用 Allthemodium 自己的升级锻造模板依次升级：
    `不毁下界合金戒指 → ATM 戒指 → 振金戒指 → 难得素戒指`。
- **能量系统**：三枚戒指的能量池分别为 **100 / 300 / 700**。能力消耗能量，最后一次消耗的 **10 秒后**开始回复，无论上限多少都在 **3 秒**内回满，期间再次受伤会打断回复。
- **能力沿链条继承**（ATM ⊂ 振金 ⊂ 难得素）：
  - **魔法内衬**（ATM）：伤害按 1:1 由能量抵挡；能量足以覆盖整次伤害时直接取消该次伤害（无击退、无红闪、不进入无敌帧）。
  - **动能偏转**（振金）：来袭弹射物被身周球形立场随机弹开；能量高于一半时不消耗能量，低于一半则失效。
  - **爆裂图腾**（难得素）：受到致命伤害时取消该次伤害并像图腾一样复活（回血、清除负面效果、生命恢复 II / 伤害吸收 II / 抗火），同时引发 8 格、20 点伤害的 TNT 式爆炸（不破坏方块，附带击退）；之后能量回复延迟变为 60 秒，且必须完全回满才能再次触发。
- **魔能增幅（Arcane Amplification）附魔**：附魔台附魔，等级 1~9，**仅限三枚联动戒指**；**能量上限 = 基础能量 × (等级 + 1)**（难得素戒指 9 级时为 7000 点）。同样会出现在村民交易与战利品中。
- **完全可选**：未安装 Allthemodium 时，上述物品、配方、附魔、标签条目**全部不会注册**，整合包不会出现缺失条目或报错。

### 新增 · HUD 与提示

- **能量条 HUD**：100×10 的能量条，数值直接显示在条内；能量回满并静止 3 秒后自动隐藏，数值一旦变化立刻重现。
- 服务端按需推送能量数据（回复中每 5 tick，满能量每 20 tick，无戒指每 80 tick），客户端按回充速率做线性插值，条子平滑增长。
- **戒指 Tooltip**：Shift 展开块按结构排列——先是能力说明（标题使用所属戒指的配色，按链条顺序排列），随后是附魔效果提示。

### 修复

- **未安装 Allthemodium 时无法进入世界**：`#simpleflightring:flight_rings` 与 `#curios:flight_ring` 标签把三枚联动戒指列为**必需**条目，导致标签加载失败，进而使 `flight_stability` / `rocket_boost` 附魔（`supported_items` 指向该标签）加载失败并中止注册表加载，游戏将世界判定为「存档数据损坏」。现已改为**可选条目**（`required: false`）；并已在 1.21.1 与 26.1.2 的开发服务器（无 Allthemodium）中验证可正常进入世界（`Done`，无标签 / 注册表错误）。
- 佩戴联动戒指时属性不生效（26.1.2）：Curios 15 通过静态 `ICurioItem.forEachModifier` 读取饰品属性，需覆写 `getDefaultCurioAttributeModifiers`（旧的实例方法 `getAttributeModifiers` 被忽略）。
- 动能偏转在 26.1.2 中「先穿透后弹开」：26.1.2 在 `ProjectileImpactEvent` 之前就应用了弹射物位移，改为在 `ServerTickEvent.Pre` 检测立场球面，弹开表现与 1.21.1 一致。
- Tooltip 中的 `\n` 在 1.21.1 会渲染为缺字方块，能力说明改为多个独立组件 / 语言键。

### 兼容性说明

- 在**没有** Allthemodium 的整合包中打开含有联动戒指的旧存档时，这三枚戒指的物品会变为空（日志提示 `Tried to load invalid item`）——这是物品未注册时的原版行为，无法避免，属预期现象。
- 其余原有功能（6 种材质戒指、不毁核心、稳定 / 动力特殊戒指、HUD 倒计时、Curios / Cloth Config / 精妙背包集成）不受影响。
